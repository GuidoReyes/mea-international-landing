# Task ID: 2

**Title:** Deploy Backend to Railway and Configure MySQL

**Status:** done

**Dependencies:** 1 ✓

**Priority:** high

**Description:** Create Railway project, add MySQL addon, configure environment variables, and establish initial deployment with health check.

**Details:**

Create new Railway project via dashboard or CLI. Connect GitHub repository to Railway (auto-deploy on main branch push). Add MySQL addon via Railway dashboard - this auto-generates DATABASE_URL. Configure environment variables in Railway: PORT (auto), DATABASE_URL (auto from MySQL addon), FRONTEND_URL=https://meainternational.com, JWT_SECRET (generate with `openssl rand -hex 32`). Set build command to `cd backend && npm install && npm run build`. Set start command to `cd backend && npm start`. Deploy and verify Railway assigns public domain. Test health check at Railway URL.

**Test Strategy:**

Verify Railway deployment completes successfully. Access https://{railway-domain}/health and confirm 200 response. Check Railway logs show server starting. Verify DATABASE_URL is available in Railway environment.

### 2.2. Add MySQL Database Addon and Configure DATABASE_URL

**Status:** pending  
**Dependencies:** 2.1  

Provision MySQL database addon through Railway dashboard and verify the DATABASE_URL environment variable is auto-generated and accessible to the backend service.

**Details:**

In the Railway project dashboard, click 'New' and select 'Database' then 'MySQL'. Railway will automatically provision a MySQL instance and generate the DATABASE_URL environment variable. This URL will be in the format: mysql://user:password@host:port/database. Navigate to the backend service settings and verify DATABASE_URL appears in the environment variables section. The database is now ready for Prisma migrations (which will be executed in Task 1's subtasks). Document the MySQL instance details (host, port, database name) for reference.

### 2.3. Configure Essential Backend Environment Variables

**Status:** pending  
**Dependencies:** 2.2  

Set up all required environment variables in Railway for backend operation including PORT, FRONTEND_URL, and JWT_SECRET.

**Details:**

In Railway backend service settings, configure the following environment variables: PORT (Railway auto-provides this, verify it exists), FRONTEND_URL=https://meainternational.com (for CORS configuration), JWT_SECRET (generate with command: openssl rand -hex 32 and paste the output). These are the minimal variables needed for initial deployment. Additional variables (META_WHATSAPP_TOKEN, META_PHONE_ID, META_WABA_ID, META_WEBHOOK_VERIFY_TOKEN, META_APP_SECRET, ANTHROPIC_API_KEY, NOTION_TOKEN) will be added in later tasks when those integrations are implemented. DATABASE_URL and REDIS_URL are auto-generated by Railway addons. Document all configured variables in a secure location.

### 2.4. Configure Build and Start Commands in Railway

**Status:** pending  
**Dependencies:** 2.3  

Set Railway build and start commands to correctly build and run the Express TypeScript backend from the /backend directory.

**Details:**

In Railway service settings, configure: Build Command: 'cd backend && npm install && npm run build' (this will install dependencies and compile TypeScript to JavaScript). Start Command: 'cd backend && npm start' (this will run the compiled backend). These commands assume the backend will have a build script in package.json that runs tsc (TypeScript compiler) and a start script that runs the compiled code with node dist/index.js. Note: The backend directory and these scripts don't exist yet (they will be created in Task 1), but configuring Railway now ensures it's ready when the code is pushed. Also configure Root Directory to 'backend' if Railway provides this option, or ensure commands use 'cd backend' prefix.
